# Harness v2 — Build Plan

The evolution of `handoff-harness` from a multi-agent persona pipeline into a
modular, document-driven harness with two dial-driven presets. This plan is
itself the first instance of the v2 conventions it describes: a bound status
block above, a closed-vocabulary lifecycle, and no external state file.

## Locked decisions

All adopted from the design conversation and the Fable adversarial review
(2026-09-13). These are settled; the build implements them.

1. **Roster collapse.** The main session is the sole builder ("Architect"). The
   only spawned agents are the review gate. The v1 persona pipeline (EM, PM, PE,
   SDE, build) moves to `legacy/`, retained for migration reference only.
2. **One axis, one flag.** The user sets **Anchor** (`outcome → spec → tdd`) and
   an **auto** flag whose halts are *derived from the anchor* (a `spec`/`tdd`
   anchor forces the spec/plan approval halt even under auto). "Lean" and
   "Standard" are named presets of Anchor, not separate harnesses.
3. **Scrutiny is a rule table**, not the builder's judgment. `scrutiny.toml`
   maps path globs / change-classes → seats. The floor is the Adversary. Auth,
   secrets, data-loss, and migrations force the full gate. The builder may only
   *escalate*, never de-escalate.
4. **The gate is a protocol**, not a fork. `{fresh context, brief, instruments,
   verdict written to the plan @sha}`. Claude Code implements it by forking;
   other tools implement it as "open a second session, run `/gate`." Seats:
   Adversary (always) + QA + Security-brief, spawned per the scrutiny table.
   Each seat writes `Gate: <verdict> r<n> @<sha> — <seat>` (seat suffix so
   multiple seats' verdicts on one doc stay distinct).
5. **State-as-document with bound markers.** No `.state/feature-state.json`, no
   inbox files. Each working doc in `docs/exec-plans/active/` carries a bound
   status block. A marker is trusted only when its `@sha`/date matches current
   content; a checker flags stale ones. Closed vocabulary — see `lib/harness-markers.md`.
6. **Region ownership, not in-file provenance markers + 3-way merge.** Every
   seeded file is split into harness-owned regions and one project-owned region
   with a fixed heading. The updater replaces harness regions and never touches
   the project region. No text merge, works offline, no marker-in-JSON problem.
7. **AGENTS.md canonical.** An index/router to the schema'd reference docs.
   CLAUDE.md is a thin wrapper (pointer + non-negotiables). The executable layer
   is generated per tool from one source.
8. **Shared file schema.** Fixed section NAMES, optional bodies. A project-owned
   `## Lessons` / attack-surfaces region the harness never regenerates (the lore
   home CLAUDE.md used to provide).
9. **Provenance.** `.harness/harness.toml` (stamp) + `.harness/manifest.lock`
   (footprint). `docs/exec-plans/` name is KEPT. Migration reads v1's
   `manifest.json` checksums to know which files are safe to delete.

## Layout

```
harnesses/
  core/         # shared spine — both presets install this
    AGENTS.md              canonical index template (region-owned)
    CLAUDE.md              thin wrapper template
    docs/                  CONTRIBUTING / ARCHITECTURE / RELIABILITY schemas
    .claude/agents/        reviewer seats: adversary, qa, security-brief
    lib/                   marker spec, checker, region-merge, install helpers
    scrutiny.toml          default scrutiny rule table
  lean/         # overlay: outcome anchor — intake, /gate, /release
  standard/     # overlay: spec/tdd anchor — register, design, plan phases
```

The top-level v1 tree stays intact until the migrator (Step 8) is proven.

### Step 1: Marker vocabulary + checker
**Objective.** A closed lifecycle vocabulary and a script that flags stale or
misfiled markers, so state-as-document cannot rot silently.
**Tests / acceptance.** A plan marked `Shipped` under `active/` is flagged. A
`Gate: APPROVED @<sha>` whose sha ≠ current content is flagged. A clean tree
exits 0. Runs from the session-start hook and pre-push.
**Demo.** `bash harnesses/core/lib/check-markers.sh docs/exec-plans` reports
zero issues on a healthy repo and names the offending file+line on a rigged one.

### Step 2: Region-ownership model + merge helper
**Objective.** Fixed region markers (`<!-- harness:region:start id=... -->` …
`end`) and an updater that replaces harness regions while preserving the one
project region. **Acceptance.** Editing the project region then re-running the
merge leaves the edit intact and refreshes harness regions. **Demo.** Round-trip
a seeded AGENTS.md through an "update" and diff shows only harness regions moved.

### Step 3: Core AGENTS.md + reference-file schema
**Objective.** The canonical index with region markers, plus schema skeletons
(fixed section names) for CONTRIBUTING / ARCHITECTURE / RELIABILITY, each with a
project-owned region. **Acceptance.** Every reference file names the same fixed
sections; a `## Lessons` project region exists and is marked never-regenerate.

### Step 4: Reviewer seats + gate protocol
**Objective.** Three seat definitions and a tool-agnostic gate spec. Adversary
refutes by measurement; QA covers correctness+security surface; Security-brief
is a section both apply, escalating to a dedicated pass on trigger. The fix loop
(findings → fix → re-confirm same seats → APPROVE) is explicit. **Acceptance.**
Gate writes `Gate: <verdict> r<n> @<sha>` into the plan; never self-merge.

### Step 5: Scrutiny rule table
**Objective.** `scrutiny.toml` — globs/classes → seats, with non-overridable
floor rows (data-loss, migrations, auth, secrets) and optional project rows that
carry a sunset condition. **Acceptance.** `git diff --name-only` maps to a seat
set; builder can escalate only.

### Step 6: Flow — five phases
**Objective.** The Architect's operating doc: Intake&anchor → Design&plan
[anchor-scaled] → Build → Gate → Verify&close, with the fix-loop back-edge and
the blast-radius-deviation halt rule (adopted from pdd code-assist).

### Step 7: Presets + dial config
**Objective.** lean/ and standard/ overlays; the collapsed dial recorded in
`harness.toml [defaults]`. **Acceptance.** Installing "lean" vs "standard"
differs only in which flow depth + overlay files land.

### Step 8: Installer + stamp + migrator
**Objective.** One script: pick preset + targets, greenfield/brownfield
identical, seed, stamp, region-merge on update. Migrator reads v1 `manifest.json`
to archive+delete the persona pipeline safely.

### Step 9: Command surface
**Objective.** Collapse eight `/prep-*` + six `/run-*` toward `/gate`,
`/release`, and one intake command.

### Step 10: Stub-repo validation loop
**Objective.** `install → seed → trivial feature → update` as a repeatable test
target, run against the stub repo.

## Non-negotiables (carry into every step)

- Never self-merge; the gate always runs (floor = Adversary).
- Trust buys fewer handoffs, never a relaxed gate.
- Keep the core lean — machinery that conflicts on high-value files gets bypassed.
- No `git add .`; stage by name. No force-push. No `--no-verify`.
